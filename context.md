# Документация проекта Cyberpunk RED Helper

## Общая архитектура

### Хранилище данных

Используется `localStorage`.

Ключи:

* `cpr_character` — персонаж
* `cpr_group` — группа
* `cpr_vehicles` — транспорт
* `wizard_progress` — прогресс конструктора персонажа
* `gm_plot_nodes` — сюжетные узлы

---

## Основная логика персонажа

Файл:

`modules/character-helper.js`

Класс:

`CharacterHelper`

Отвечает за:

* отображение карточки персонажа;
* редактирование персонажа;
* применение модификаторов имплантов;
* экспорт и импорт JSON;
* синхронизацию данных между вкладками.

---

## Конструктор персонажа

Файл:

`modules/wizard/wizard-core.js`

Класс:

`CharacterWizard`

Особенности:

* пошаговый мастер создания персонажа;
* шаги: `0–10`;
* данные хранятся в `this.data`;
* при сохранении персонаж записывается в `localStorage` под ключом `cpr_character`.

---

## Редактор характеристик и навыков

Расположение:

Вкладка **«ХАР & Навыки»** в `main.js`.

Особенности:

* работает с `baseStats`;
* изменяет базовые характеристики персонажа;
* после сохранения пересчитывает итоговые характеристики.

---

## Терминал

Поддерживает:

* анимированную загрузку;
* систему команд;
* темы оформления.

Основные команды:

* `help`
* `roll`
* `theme`
* и другие.

# Ключевые исправления

## Броня в конструкторе

### wizard-core.js

Метод:

```js
updateGearFromDOM()
```

Читает чекбоксы брони:

```html
data-type="armorBody"
data-type="armorHead"
```

---

### attachGearEvents()

Добавлена логика переключателей:

* можно выбрать только одну броню для тела;
* можно выбрать только одну броню для головы.

---

### wizard-step-summary.js

Итоговая информация берётся из:

```js
data.gear.armor
```

а не напрямую из DOM.

Броня корректно сохраняется и отображается.

---

## Импланты влияют на характеристики

Файл:

`character-helper.js`

Метод:

```js
applyCyberwareModifiers()
```

Особенности:

* учитывает все импланты из `data.js`;
* работает с `baseStats`;
* изменяет итоговые характеристики персонажа.

Поддерживаемые характеристики:

* BODY
* MOVE
* REF
* DEX
* Initiative
* Perception
* Resistance

---

### Поиск имплантов

Поиск:

* регистронезависимый;
* по частичному совпадению.

Пример:

```js
name.includes('искусственные мышцы')
```

---

### Отображение карточки

Метод:

```js
displaySavedCharacterCard()
```

Алгоритм:

1. Берутся `baseStats`.
2. Применяются модификаторы имплантов.
3. Отображаются итоговые значения.

---

### Редактирование карточки

В поля ввода записываются:

```js
baseStats
```

После сохранения:

1. пересчитываются модификаторы;
2. обновляется отображение персонажа.

---

## Экспорт и импорт персонажа

### Экспорт

В JSON сохраняются:

```js
baseStats
```

отдельно от итоговых характеристик.

---

### Импорт

Если отсутствует:

```js
baseStats
```

то:

1. создаётся из текущих характеристик;
2. старые поля удаляются.

Удаляемые поля:

```js
INT
REF
DEX
TECH
COOL
WILL
LUCK
MOVE
BODY
EMP
```

После импорта карточка автоматически перерисовывается.

---

## Редактор характеристик

Вкладка:

**«ХАР & Навыки»**

Особенности:

* работает только с `baseStats`;
* после сохранения пересчитывает модифицированные значения;
* для обратной совместимости записывает значения также в:

```js
char.INT
char.REF
char.DEX
...
```

# Текущие ограничения и недоделки

## 1. Редактирование характеристик

При изменении базовых характеристик бонусы имплантов продолжают применяться поверх них.

Пример:

```text
BODY (база): 6
Имплант: +2 BODY
Итог: 8
```

Если пользователь изменит базу:

```text
BODY (база): 8
Имплант: +2 BODY
Итог: 10
```

Это корректное поведение, но может быть неочевидно для пользователя.

---

## 2. Бонусы инициативы, восприятия и сопротивления

Служебные поля:

```js
_initiativeBonus
_perceptionBonus
_resistanceBonus
```

Отображаются в карточке персонажа, но пока не используются:

* калькулятором боя;
* расчётом инициативы;
* другими игровыми подсистемами.

---

## 3. Устаревший код брони

Файл:

```text
wizard-step-gear.js
```

Содержит старую логику на основе:

```html
data-slot
```

Текущая рабочая система использует:

```html
data-type
```

Функционально не мешает, но может вводить в заблуждение при поддержке проекта.

---

## 4. Ограничение cyberpunk-theme

Для корректной работы выпадающих списков временно отключён:

```css
clip-path
```

Для элементов:

```css
select {
    clip-path: none !important;
}
```

Причина:

выпадающие списки обрезались нестандартной формой элементов интерфейса.

Статус: временное решение.
